# Repair-WinRE

До запроса подтверждения скрипт пытается использовать уже установленный 7-Zip строго по официальному пути `Program Files\7-Zip\7z.exe` (на 32- и 64-битной Windows) для прямого извлечения `Winre.wim` из `install.wim`/`install.esd`. PATH и `Program Files (x86)` не проверяются. Сторонние программы не входят в комплект и не скачиваются. Если 7-Zip отсутствует или результат не прошёл проверку, автоматически применяется штатный DISM; для него может потребоваться больше свободного места. В сводке отображается способ извлечения. Штатный вывод программ сохраняется.

**Repair-WinRE** — интерактивная утилита диагностики и восстановления среды Windows Recovery Environment (WinRE). Работает в **Windows PowerShell 5.1** с базовыми дисками GPT/MBR. Если локального образа нет, умеет извлекать `Winre.wim` из установочного ISO Windows.

**[Основная документация на английском](README.md)**

> **Внимание!** Программа может отформатировать или удалить существующий раздел восстановления, а также увеличить C:. **Перед использованием сделайте полный резервный образ диска либо проверенную контрольную точку виртуальной машины.** Автоматического отката нет. Сначала проверьте программу на тестовой VM.

## Запуск

Из корня PSWinKit выполните:

```powershell
.\Repair-WinRE\Repair-WinRE.ps1
```

Обязательных параметров нет. Можно запустить `Repair-WinRE.ps1` из папки утилиты или выбрать «Выполнить с помощью PowerShell». Сохраняйте структуру PSWinKit: библиотека `..\Common\Common.ps1` подключается относительно скрипта, независимо от текущего рабочего каталога.

`Start-Utility` выбирает язык, выводит заголовок Repair-WinRE, запускает отсчёт времени и при необходимости запрашивает UAC. Через UAC открывается отдельное окно с тем же основным скриптом и той же разрядностью PowerShell. Исходная консоль сразу возвращается к приглашению; отмена UAC не запускает работу. После очистки ресурсов `Stop-Utility` выводит время окончания и длительность. В существующем терминале лишней паузы нет; в окне, открытом Common через UAC, есть финальное ожидание клавиши. Запуск из проводника определяется по возможности. Собственной реализации UAC и паузы у утилиты нет.

Сообщения утилиты, включая ошибки и заголовки таблицы ISO, хранятся в секциях `Repair-WinRE` файлов `Common/Languages/en.psd1` и `ru.psd1`. Язык определяется по языку интерфейса Windows с резервным английским. Штатный вывод DISM, DiskPart, REAgentC, 7-Zip и системных исключений сохраняется и повторно не переводится. У DISM сохранён исходный параметр `/English`. Формат чисел, дат и времени определяется региональными настройками независимо от языка интерфейса. Подробнее — [контракт Common](../Common/README.ru.md).

Сценарий: **анализ → итоговый план → одно подтверждение `Y/N` → выполнение**. Этапы, предупреждения и результаты разделены отступами и спокойными цветами; подписи и значения выровнены по колонкам с пробелами. Любой ответ кроме `Y` означает отмену. Файлы журналов не создаются.

Если WinRE уже включена (`Enabled`), программа ничего не изменяет. Если выключена (`Disabled`), сначала проверяется локальный `Winre.wim`. Для `%WINDIR%\System32\Recovery`, `C:\Recovery\WindowsRE` и существующего Recovery-раздела отдельно выводятся результаты поиска и проверки образа (отсутствует, непригоден или найден). Постоянный файл `Winre.wim` сохраняется на разделе Recovery: дублировать его в системной папке Windows не требуется. При отсутствии подходящего образа программа попросит подключить установочный ISO соответствующей редакции и сборки, затем указать **букву диска без двоеточия** (`F`). Поддерживаются `sources\install.wim` и `sources\install.esd`.

Редакция сопоставляется по `EditionId`, архитектура — независимо от языка Windows. При выборе ISO программа сначала ищет точное совпадение сборки; для Windows 11 24H2/25H2/26H2 допускает единственный подходящий образ из общего семейства сборок 26100/26200/26300 с предупреждением. Для диагностики выводит индексы, редакции, сборки и архитектуры доступных образов. Образ извлекается во временную папку на C: до подтверждения и проверяется. Минимум для Recovery: `max(990 МиБ, размер Winre.wim + 250 МиБ + 32 МиБ)`. Перед подтверждением показываются фактическая ёмкость диска и оставшееся нераспределённое пространство; рассчитанные границы C: и Recovery дополнительно проверяются в байтах на выход за пределы диска и пересечение с другими разделами. После нажатия `Y` программа сначала пробует обычный `reagentc /enable`, **только если раздел Recovery существует**. Если Recovery отсутствует, скрипт не пытается включить WinRE на C: и преждевременно завершить работу: он создаёт отсутствующий раздел.

## Какие схемы поддерживаются

| Разметка | Действия при невозможности включить WinRE штатно |
|---|---|
| `C: → Recovery → свободное место` | Удаляем старый Recovery, при возможности расширяем C: до целого числа ГиБ с дополнительным 1 МиБ для корректного отображения NTFS в проводнике и создаём новый Recovery. Уменьшения C: нет. |
| `C: → Recovery → D:` | Если Recovery достаточного размера, форматируем и восстанавливаем WinRE **на том же месте**. C: и D: не изменяются. Если места мало — выходим без переразметки. |
| `C: → свободное место` | Создаём Recovery, если свободной области достаточно. Не включаем WinRE на C: вместо создания отсутствующего раздела. |
| `C: → D:` без Recovery | Пока не поддерживается: программа ничего не перемещает и не уменьшает. |

**Recovery между C: и D: — нормальное и рекомендуемое Microsoft расположение.** Переносить раздел восстановления за D: не требуется. Если размер Recovery недостаточен, в будущей версии планируем уменьшать C: и пересоздавать Recovery перед D:, не затрагивая D:.

При создании нового Recovery программа устанавливает GPT GUID `DE94BBA4-06D1-4D40-A16A-BFD50179D6AC` и атрибуты восстановления, либо MBR тип `0x27`. Для нового раздела C: по возможности используется целое число ГиБ + 1 МиБ: NTFS может показывать ёмкость на один кластер меньше самого раздела, из-за чего проводник отображал 64,9 вместо 65,0. Итог проверяем на Windows. Recovery временно подключается к отдельной пустой папке NTFS в `%WINDIR%\Temp` **без назначения буквы диска**; после регистрации точка подключения удаляется, затем устанавливаются тип и атрибуты Recovery. Если отключить точку подключения не удаётся, папка сохраняется для проверки. Атрибуты GPT сверяются через DiskPart, а не по пустому `Get-Partition.NoDefaultDriveLetter`. Максимум для перестраиваемого Recovery — рассчитанный минимум + 1024 МиБ; остаток по возможности отдаётся C:, чтобы его размер был целым числом ГиБ.

## Ограничения безопасности

- Нужны права администратора, Windows на **C:**, Windows 10/11 либо Windows Server 2016 и новее с необходимыми штатными инструментами. Основная цель — Windows 11.
- Не трогаем неизвестные разделы и OEM-данные восстановления. Содержимое существующего Recovery должно быть доступно для проверки.
- Не форматируем D:, не перемещаем разделы и не уменьшаем C: в этой версии.
- Не изменяем системные тома с BitLocker или при невозможности проверить его состояние.
- До подтверждения структура диска не меняется; извлечение ISO временно занимает место на C:. Временные файлы создаются в `%WINDIR%\Temp\WinRE-Manager-<GUID>`, а полный путь к WIM показывается перед экспортом. DISM выводит свой штатный индикатор прогресса непосредственно в консоль, без обёртки PowerShell. Скрипт также показывает путь монтирования, путь извлечённого Winre.wim и результат проверки образа, чтобы назначение монтирования и размонтирования было очевидным.
- После ошибки, произошедшей уже после удаления/форматирования, временная копия `Winre.wim` сохраняется для ручного восстановления. Автоматического отката разметки нет.
- При прерывании **Ctrl+C** скрипт пытается очистить временные ресурсы и выводит заметное красное сообщение **ОПЕРАЦИЯ ПРЕРВАНА**, а не только приглашение нажать клавишу. Если операции с разделами уже начались, перед повторным запуском необходимо проверить состояние диска и WinRE. Принудительное завершение процесса не гарантирует очистку и вывод сообщения.
