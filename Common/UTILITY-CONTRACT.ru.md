# Единый контракт PowerShell-утилит

## Область применения

- Windows 10+, Windows PowerShell 5.1, x86/x64.
- Общая библиотека `Common/Utility.ps1` подключается через dot-sourcing (`.`).
  Самостоятельного процесса UtilityHost нет.
- Обязательных параметров запуска нет; локализация, UAC, заголовок и
  завершение стандартизированы.
- `.ps1` и `.psd1` — UTF-8 BOM для корректной работы Windows PowerShell 5.1.
- Публичные функции жизненного цикла: **`Start-Utility`** и **`Stop-Utility`**.
  Библиотека также содержит вспомогательную `Get-UtilityMessage`.

## Структура

```text
Remove-Paths.ps1
WinRE-Manager.ps1          # в перспективе
WinRepair.ps1              # в перспективе
Common/
  Utility.ps1
  Languages/
    en.psd1
    ru.psd1
  UTILITY-CONTRACT.md
  UTILITY-CONTRACT.ru.md
```

## Шаблон утилиты

```powershell
param(
    [string]$LanguageFile,
    [switch]$PauseOnExit
)

. (Join-Path $PSScriptRoot 'Common\Utility.ps1')

$utility = Start-Utility -ScriptPath $PSCommandPath -Section 'RemovePaths' `
    -LanguageFile $LanguageFile -PauseOnExit:$PauseOnExit -RequireAdministrator

if ($null -eq $utility) { return }

$messages = $utility.Messages
try {
    # Основная логика; собственная обработка ошибок
}
finally {
    # Собственная итоговая сводка
    Stop-Utility -Context $utility
}
```

`-Section` — название раздела PSD1, содержащего `Title`. Если утилите не
требуются администраторские права, она не передаёт `-RequireAdministrator`.

## Семантика Start-Utility

- Выбирает PSD1 (при отсутствии явного пути по `Get-UICulture`), контролирует
  права и при необходимости запрашивает UAC.
- Если прав достаточно, загружает один PSD1, показывает заголовок и возвращает
  контекст с `LanguageFile`, `Messages` и `PauseOnExit`.
- Если успешно начат новый экземпляр через UAC, возвращает **`$null`**;
  исходная утилита немедленно выходит через `return`, без работы и `Stop-Utility`.
- При отказе пользователя от UAC (`ERROR_CANCELLED`, 1223) также возвращает
  **`$null`**. Нет удаления, сводки и запроса клавиши.
- Другие ошибки запуска/повышения прав **не** скрываются: они приводят
  к исключению.
- Повышенный экземпляр запускается с абсолютным `-LanguageFile` и
  `-PauseOnExit`. Файлы переводов выбираются до UAC, чтобы смена учётной
  записи администратора не меняла язык.
- Не передаёт между процессами ни хеш-таблицы, ни сериализованные сообщения.
- В уже повышенном процессе никакого повторного запуска нет.

## Семантика Stop-Utility

- Вызывается только после успешной инициализации, предпочтительно из
  `finally` после итоговой сводки утилиты.
- Опционально ожидает клавишу, если запуск был самостоятельным (например,
  из Проводника) или передан `-PauseOnExit`.
- Не делает ничего при работе из существующего терминала без `-PauseOnExit`.
- После отказа от UAC **не вызывается вообще**.

## Параметры

- `[string]$LanguageFile` и `[switch]$PauseOnExit` объявляются в каждой
  утилите явно. Это простая и прозрачная стандартная модель PowerShell.
- `-LanguageFile` задаёт имя PSD1 в `Common/Languages` или абсолютный путь;
  явно заданный отсутствующий/не-PSD1 файл — ошибка.
- `-PauseOnExit` служебный, но может быть передан явно пользователем.
- При UAC перезапускается исключительно **основной скрипт** через
  `Start-Process -Verb RunAs`, не библиотека.

## Языки PSD1

- `Common/Languages/<culture>.psd1` — штатная загрузка
  `Import-PowerShellDataFile -LiteralPath`, без собственного INI/JSON-парсера.
- Алгоритм: полная культура → родители культуры → всегда `en.psd1`.
  Например, `ru-RU.psd1` → `ru.psd1` → `en.psd1`.
- Загружается **один** файл; `en.psd1` обязателен и служит резервным языком.
- Сейчас поддерживаются `ru.psd1` и `en.psd1`. При добавлении языка
  обеспечить одинаковый набор секций и ключей.
- Общие разделы: `Common` (переиспользуемые сообщения), `Host` (UAC, пауза),
  `RemovePaths` / `WinREManager` / `WinRepair` (сообщения конкретных утилит).
- Ключи латиницей, строки в одинарных кавычках, апостроф `''`, позиционные
  маркеры `String.Format` — `{0}`, `{1}`, ... .
- Внутри утилиты сообщения доступны как `$utility.Messages` или `$messages`;
  отдельного чтения PSD1 не требуется.

## Обработка ошибок и безопасность

- Для опасных операций обязателен предпросмотр и `Y/N` без умолчания.
- Удаление без корзины должно сопровождаться заметным предупреждением до ввода
  путей и безвозвратным подтверждением перед операцией.
- В Remove-Paths используется сквозная нумерация введённых путей и пустой
  Enter для окончания ввода. Перед подтверждением показываются только числа
  целей и пропусков (с причинами пропуска по номерам), без повторения путей.
  Итоговая сводка перечисляет только не полностью удалённые пути с их
  первоначальными номерами и именами, затем число полностью удалённых путей,
  файлов внутри них и пропущенных при проверке. Ссылки и каталоги не считаются
  файлами; файлы из частично удалённых путей не входят в итоговый счётчик.
- Итоговая сводка печатается самой утилитой из `finally` при нормальном
  завершении и стандартном `Ctrl+C`, когда PowerShell выполняет раскрутку
  стека. Принудительное завершение процесса не покрывается.
- Удаление и изменение владельца/ACL не должны переходить по junction,
  symlink, NTFS mount points. Удаляется ссылка, не её цель.
- Системные пути работающей Windows и `C:\Users` с любыми подпапками
  защищены от удаления.
- README содержит только постоянные инструкции и ограничения, без временных
  заметок о тестировании.
- Коммиты в Git: короткие `Title` и `Description` на английском языке.

## Диагностика и длительность

Remove-Paths при входе в каждый настоящий каталог использует Windows AuthzAccessCheck для проверки прав LIST_DIRECTORY и DELETE_CHILD; исправление при необходимости локально, ACL → владелец → ACL, без рекурсивной смены разрешений. Удаление файлов производится сразу, исправление прав — после отказа. Все NTFS-ссылки удаляются без перехода к целям. В начале и конце работы показывать региональные дату и время с секундами, итоговую длительность `чч:мм:сс`, а при наличии дней — число с группировкой разрядов и локальным суффиксом `д`/`d`.
