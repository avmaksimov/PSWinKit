# PSWinKit — контракт разработки PowerShell-утилит

Этот файл — одновременно документация `Common/Common.ps1` и обязательный контракт для `Remove-Paths`, `Repair-Windows`, `Repair-WinRE` и других утилит PSWinKit. Английский эквивалент: [README.md](README.md).

## 1. Назначение и принципы

- Утилита полноценно запускается **без обязательных параметров**. Собственные необязательные параметры допустимы.
- Общие механизмы языка, заголовка, повышения прав, времени и завершения сосредоточены в `Common/Common.ps1`.
- Утилита владеет своей основной логикой, предупреждениями, прогрессом и итоговой статистикой.
- Не создавать отдельные `UtilityHost`, `ElevatedHost` и аналогичные процессы-обёртки; через UAC перезапускается **основной PS1-файл**.
- Не переносить в Common специфичную логику одной утилиты и не усложнять архитектуру на будущее без практической причины.
- Контракт определяет целевое поведение. Работу необходимо проверять на поддерживаемых версиях Windows.

## 2. Требования и кодировка

Базовые требования: **Windows 10+, Windows Server 2016+, Windows PowerShell 5.1**, x86/x64 — где применимо. Не требовать PowerShell 7+, неподдерживаемые старые ОС или сторонние зависимости для общей библиотеки.

Все `.ps1` и `.psd1` хранить в **UTF-8 с BOM**. Файлы документации — Markdown; тексты на английском и русском должны быть содержательно эквивалентны.

```text

├── install.ps1

├── Common/
│   ├── Common.ps1

│   ├── README.ru.md
│   └── Languages/

│       └── ru.psd1
├── Remove-Paths/
│   ├── Remove-Paths.ps1
│   ├── README.md
│   └── README.ru.md
├── Repair-Windows/

└── Repair-WinRE/
    ├── Repair-WinRE.ps1
    ├── README.md
    └── README.ru.md
```

Каждая следующая утилита получает свой каталог, но все переводы хранятся централизованно в Common/Languages. Утилиты подключают общую библиотеку относительно своего `$PSScriptRoot`:

```powershell
. (Join-Path $PSScriptRoot '..\Common\Common.ps1')
```

Копировать Common в каталоги утилит нельзя. Искать **ресурсы утилит** относительно текущего рабочего каталога нельзя. **Каталог установки** — предусмотренное исключение:

`update.ps1` — независимый англоязычный загрузчик, не использующий Common. Он проверяет новый коммит на GitHub и запускает свежий `install.ps1` из скачанного архива. `install.ps1` использует Common и переводы из этого же архива. Оба скрипта устанавливают файлы в **текущий рабочий каталог**. Локальный `install.psd1` хранит список установленных файлов и сведения о коммите. Команды установки и обновления приведены в корневом README.

## 4. Параметры основных утилит

Запуск без параметров обязателен:

```powershell
.\Remove-Paths.ps1
```

Собственные необязательные параметры, например `[string[]]$Paths` или `[switch]$DryRun`, допустимы. Основным утилитам **не нужно объявлять** `LanguageFile`, `PauseOnExit`, `RequireAdministrator` или `ScriptArguments` ради работы Common. Последний параметр в API Common отсутствует.

При UAC-перезапуске Common получает `$PSBoundParameters` **непосредственного вызывающего скрипта** через `Get-Variable -Name PSBoundParameters -Scope 1` в самом начале `Start-Utility`. Поэтому `Start-Utility` вызывается только **на верхнем уровне основного скрипта**, а не из дополнительной функции.

Сохраняются явно переданные значения `String`, `Boolean`, `SwitchParameter`, обычных числовых типов и одномерных массивов этих типов; включая явно переданный `$false`, пустые строки и пустые массивы. Значения по умолчанию, не переданные явно, определяются основной утилитой заново. Сложные объекты, `SecureString`, `PSCredential`, `ScriptBlock`, секреты и произвольные объекты **не имеют универсальной поддержки**: необходимо выдать понятную ошибку **до** перезапуска, не теряя значения молча. Необъявленные позиционные аргументы, `$args`, pipeline input и состояние процесса не переносятся автоматически.

## 5. Публичные функции

У Common **две публичные функции**:

| Функция | Назначение |
| --- | --- |
| `Start-Utility` | Параметры запуска, выбор языка, UAC при необходимости, заголовок и начало отсчёта |
| `Stop-Utility` | Время окончания, общая длительность, финальная пауза |

Внутренние вспомогательные функции допустимы, но не образуют обязательный публичный API. Отдельная функция `Get-UtilityMessage` не нужна: сообщения утилиты доступны через `$utility.Messages`.

## 6. Start-Utility

Обычный вызов утилиты, которой необходимы права администратора:

```powershell
$utility = Start-Utility -ScriptPath $PSCommandPath -RequireAdministrator
if ($null -eq $utility) { return }
```

Для утилит, которым повышение не нужно, `-RequireAdministrator` опускается.

| Параметр | Тип | Обязателен | Значение по умолчанию |
| --- | --- | --- | --- |
| `ScriptPath` | `[string]` | Да | — |
| `RequireAdministrator` | `[switch]` | Нет | `$false` |
| `LanguageFile` | `[string]` | Нет | Не указан |
| `PauseOnExit` | `[switch]` | Нет | `$false` |

`ScriptPath` — `$PSCommandPath` основного скрипта. Из него определяются секция переводов (имя скрипта без расширения), заголовок и путь перезапуска. Отдельные параметры `Utility`, `Program` или `Section` не используются.

**RequireAdministrator.** Проверяет эффективный повышенный токен (включённую роль Administrators), а не только принадлежность учётной записи группе. При отсутствии требуемых прав запускает UAC. В повышенном процессе проверка повторяется. Если повышение не требуется, UAC не появляется.

**LanguageFile.** Необязательная возможность для разработчика, вызывающего `Start-Utility`. По умолчанию `Get-UICulture`: точный файл (`ru-RU.psd1`) → родительский (`ru.psd1`) → обязательный `en.psd1`. Явно заданный относительный путь разрешается относительно **Common/Languages**; отсутствующий файл или файл не PSD1 — ошибка. Выбранный файл сохраняется при UAC, даже если пользователь/язык Windows изменятся. Основным утилитам не требуется объявлять собственный параметр `-LanguageFile`.

**PauseOnExit.** Принудительная пауза по запросу разработчика; также обязательна в интерактивном окне, созданном Common через UAC. В существующей консоли не требуется, если не запрошена явно. Определение запуска из Проводника — best effort; неинтерактивные запуски не должны намеренно блокироваться. Отмена UAC не приводит к паузе.

**Возврат.** При успехе возвращается объект `$utility` с `StartedAt`, таймером, `Messages`, выбранным языком и признаком паузы. Если выполнение передано новому процессу либо пользователь отменил UAC, возвращается `$null`; исходный экземпляр сразу заканчивается **без сводки и Stop-Utility**. Ошибки инициализации диагностируются отдельно.

## 7. Заголовок и время начала

После успешной проверки прав `Start-Utility` **как можно раньше** фиксирует время начала и запускает независимый монотонный таймер `Stopwatch`, до вывода заголовка и выполнения логики утилиты. Ожидание UAC в исходном процессе не учитывается. Заголовок берётся из поля `Title` **секции утилиты**; служебное `Started` — только из Common:

```text
=== Удаление файлов и каталогов ===
Начало: 31.10.2026 22:42:39

```

После двух строк печатается одна пустая строка; утилита не повторяет начало и заголовок. **Дата и время берутся из региональных настроек `CurrentCulture` Windows**, всегда с секундами; язык интерфейса их не определяет. Пример выше только иллюстрация, а не фиксированная маска даты.

## 8. Повышение прав через UAC

1. Определить, нужны ли права и есть ли уже повышенный токен.
2. Если повышение нужно, в начале `Start-Utility` считать явно заданные параметры непосредственного вызывающего скрипта и проверить их поддерживаемые типы.
3. Сериализовать параметры штатным `System.Management.Automation.PSSerializer` с сохранением значений и типов.
4. Подготовить команду для **того же основного PS1**, защитив пути, строки и параметры от внедрения кода. Допустим `powershell.exe -EncodedCommand` с UTF-16LE; Base64 **не шифрует данные**.
5. Через `Start-Process -Verb RunAs` запустить одноимённую разрядность PowerShell, восстановить параметры и применить splatting. Выбранный язык и режим паузы передать внутренним способом Common, не создавая обязательных параметров основного скрипта.
6. После успешного запуска нового процесса исходный возвращает `$null`; повышенный экземпляр сам подключает Common и вызывает `Start-Utility`.

Требования безопасности: не использовать `Invoke-Expression`, не подставлять пользовательские строки в исполняемый код, поддерживать кавычки/апострофы/кириллицу/пробелы, проверять длину команды, по возможности обходиться без временных файлов, не передавать секреты через аргументы. Не менять разрядность без причины, по возможности сохранять рабочий каталог с учётом недоступности сетевых дисков после повышения. **Не использовать `-ExecutionPolicy Bypass` и не обходить политики PowerShell.** В повышенном процессе утилита заново проверяет входные данные и защищённые пути.

Если пользователь отменяет UAC (`ERROR_CANCELLED`, 1223), текущий скрипт завершается без операции, сводки, паузы и имитации ошибки удаления. Другие ошибки запуска нового процесса диагностируются явно.

## 9. Локализация и границы ответственности

`Common/Languages/en.psd1` и `ru.psd1` содержат все переводы PSWinKit, разделённые по вложенным секциям: `Common`, `Remove-Paths`, `Repair-Windows`, `Repair-WinRE`, `install`. Имя секции утилиты совпадает с именем основного `.ps1` без расширения. Каждая утилита по-прежнему получает **плоскую** таблицу `$utility.Messages` со своими фразами; служебные строки жизненного цикла читает только Common. Пример:

```powershell
# Common/Languages/ru.psd1 (фрагмент)
@{
    Common = @{ Started = 'Начало: {0}' }
    'Remove-Paths' = @{ Title = 'Удаление файлов и каталогов' }
    'Repair-Windows' = @{ Title = 'Восстановление Windows' }
    'Repair-WinRE' = @{ Title = 'Repair-WinRE — восстановление WinRE' }
    install = @{ Title = 'Установка и обновление PSWinKit' }
}
```

`Start-Utility` выбирает секцию из PSD1 языка интерфейса Windows, а отсутствующие ключи дополняет из **той же секции** `en.psd1`. Отсутствие английской секции или обязательного `Title` — ошибка. Утилиты не обращаются напрямую к секции `Common`. Явный параметр разработчика `LanguageFile` указывает на PSD1 из Common/Languages либо на абсолютный путь. Дополнительных публичных функций не требуется.

**Правило оформления консоли:** В переводах хранятся только тексты сообщений и шаблоны подстановки — без декоративных начальных/конечных переводов строк, пустых строк, цветов и разделителей блоков. Смысловые разделители задаются в вызывающем `.ps1` явным `Write-Host ''` (или аналогом). Имена ключей отражают содержание, а не оформление: `CheckingSystemFilesSFC`, а не `NCheckingSystemFilesSFC`. Перенос строки внутри перевода допустим **только** как содержательная часть настоящего многострочного сообщения (например, заголовок диагностики с последующим исходным выводом внешней команды). Возврат каретки для обновления строки прогресса, а также переводы строк при разборе и сериализации данных не относятся к разделителям консольных блоков. Правило распространяется на Common, все утилиты, установщик, обновление и будущий код.

**Отдельное правило:** `CurrentCulture` определяет формат дат, времени и длительности; `Get-UICulture` — язык фраз. Например, русский интерфейс может сочетаться с английским форматом даты. Разделитель часов/минут/секунд длительности берётся из регионального формата времени. Если длительность больше суток, показывается количество дней с локализованным суффиксом (`1д 03:24:15` или `1d 03:24:15`, где двоеточие — лишь пример разделителя). В утилитах, самостоятельно отображающих длительности отдельных операций, применяется тот же принцип. Форматы **не фиксируются** как `dd.MM.yyyy HH:mm:ss` или `d.hh:mm:ss`.

## 10. Stop-Utility

```powershell
Stop-Utility -Utility $utility
```

Обязательный параметр `Utility` — объект, ранее возвращённый `Start-Utility`. Повторно указывать путь, язык или название не нужно. `Stop-Utility` **непосредственно при вызове** останавливает общий таймер и фиксирует время окончания. После собственной сводки утилиты выводит **одну пустую строку** и две служебные строки, светло-серым (`Gray`):

```text
Окончание: 31.10.2026 22:43:12
Длительность: 00:00:33
```

Дата и длительность региональные по правилам раздела 9. Надпись «Окончание» нейтральна и не означает успешного выполнения каждого действия. Итог, ошибки и числовую сводку утилита выводит сама **перед** `Stop-Utility`. После служебных строк выполняется необходимая финальная пауза. Дополнительная общая сводка Common не создаётся.

`Stop-Utility` вызывается только после успешного `Start-Utility`, желательно в `finally`. Обычный `Ctrl+C` может позволить вывести сводку, но принудительное завершение процесса не гарантирует выполнение `finally`.

## 11. Базовый шаблон утилиты

```powershell
#requires -Version 5.1
# Собственные НЕОБЯЗАТЕЛЬНЫЕ параметры (если есть) объявляются здесь.

. (Join-Path $PSScriptRoot '..\Common\Common.ps1')
$utility = Start-Utility -ScriptPath $PSCommandPath -RequireAdministrator
if ($null -eq $utility) { return }

try {
    Write-Host $utility.Messages.WarningTitle
    # Здесь собственная логика утилиты.
}
catch {
    # Диагностика ошибки утилиты.
}
finally {
    # Сначала собственная сводка, если нужна.
    Stop-Utility -Utility $utility
}
```

Если права администратора не нужны, `-RequireAdministrator` опускается. `Start-Utility` должен вызываться непосредственно на верхнем уровне основного скрипта, чтобы правильно получить параметры для UAC.

## 12. Документация

- **Корень:** `README.md` и `README.ru.md` — обзор набора, перечень доступных/планируемых утилит, требования, лицензия и ссылки.
- **Common:** эти два README — **полный технический контракт**, API, UAC, локализация, время и жизненный цикл. Отдельных `CONTRACT.md`, `UTILITY-CONTRACT.md` и их переводов **нет**.
- **Каждая утилита:** свои `README.md` и `README.ru.md` — назначение, возможности, запуск, собственные параметры, примеры, ограничения и предупреждения.

Не дублировать полный контракт в корневых README или внутри утилит; достаточно ссылок.

## 13. Общие правила разработки

Предпочитать простой, сопровождаемый код и штатные механизмы PowerShell 5.1. Менять согласованные алгоритмы удаления или восстановления исключительно ради косметического рефакторинга нельзя. Для `DISM`, `SFC`, `CHKDSK` и аналогичных команд по возможности сохранять штатный вывод. Для настроек, локализации и машинно изменяемого состояния использовать PSD1. Результаты критических операций проверять и диагностировать. Для Git-коммитов предлагать короткие **Title** и **Description** на английском.

## 14. Изменение контракта

Контракт описывает **текущую** архитектуру. Номера редакций контракта и требования обратной совместимости с прежними редакциями не вводятся. При изменении Common одновременно обновлять **оба** `Common/README.*`, при необходимости корневые README и документацию затронутых утилит; проверять Windows PowerShell 5.1 на реальной Windows. Правила, относящиеся только к одной утилите, записываются в её README и не становятся автоматически частью общего контракта.

**Основной принцип:** единая инфраструктура, независимые утилиты, запуск без обязательных параметров и минимальная сложность.
